# Shared operating workflow

This file defines the common workflow across the three projects housed in this repository. It standardises how agents work; it does not standardise what each project considers admissible.

## Before starting
- Read `AGENTS.md`.
- Identify the project and read its methodology.
- Read the latest collaboration log and inspect existing records.
- Work only in this repository. Legacy repositories are reference-only.

## Track A — discover new leads
1. Search broadly, including local-language and specialist sources where relevant.
2. Capture the exact object or claim, not just a promising title or search snippet.
3. Record source URL, source title / institution, access date, relevant page / item / track, original-language names, and a concise evidence note.
4. State why the lead fits this project's own scope.
5. Assign a provisional status and confidence without implying acceptance.
6. Deduplicate against existing records and note the next verification action.

## Track B — advance existing leads
1. Verify identity, dates, credits, versions, and provenance against primary or specialist sources.
2. Update the project's canonical catalogue / compendium / cue or mix data, preserving its own schema and editorial criteria.
3. Separate research confidence, project eligibility, audio existence, audio retrieval, and rights / reuse status.
4. Where audio retrieval is appropriate, create a precise request for a Drive-enabled agent: exact target, preferred source, source URL, object/version, filename suggestion, project destination, and rights/access caveat.
5. A request is not a download; a download report is not independent file verification; public access is not reuse clearance.

## Asset-request hand-off
Each request should include: project, stable record ID, target recording / cue / release, exact edition or version, source URL and access conditions, desired format if known, suggested filename, destination folder, retrieval status, and rights note. Drive-enabled agents report the exact resulting filename, Drive link, source, format, size/duration where available, and any failure. Never invent Drive links or claim access you do not have.

## Evidence and editorial safeguards
- Cite claims close to where they appear.
- Preserve original scripts, aliases, transliterations, and conflicting dates.
- Distinguish primary evidence, scholarly interpretation, collector testimony, and unverified leads.
- Do not conflate a composition, performance, recording, issue, transfer, film mix, reconstruction, dub, or compilation.
- Keep project-specific ethical safeguards, inclusion thresholds, and rights review intact.

## Collaboration
Use the relevant project's existing log where it has been migrated; otherwise use a clearly labelled project section in the shared collaboration log. Claim bounded work, avoid overwriting active work, and append a dated DONE / PARTIAL / BLOCKED hand-off. Record files changed, sources, findings, confidence, unresolved questions, and next action.
